# officev2 Architecture

Status: design document. No code exists yet; everything below is the intended design.

## 1. Goals and constraints

- Everything runs on the user's machine. No cloud API is required for any core feature.
- Small base install; heavy AI/media capabilities are optional and downloaded on demand.
- Destructive operations are always previewable and reversible.
- The local HTTP API must not be reachable by arbitrary web pages or other local users.

## 2. High-level layout

```
┌──────────────────────────── Tauri shell (Rust) ────────────────────────────┐
│ tray · global hotkeys · clipboard watcher · screen capture / overlays      │
│ file watcher (notify) · disk scanner (walkdir) · updater · sidecar manager │
└───────────────┬─────────────────────────────────────────┬──────────────────┘
                │ Tauri IPC (invoke / events)             │ spawn + supervise
        ┌───────▼────────┐                       ┌────────▼───────────────────┐
        │ React UI (Vite)│── HTTP/SSE/WS ───────▶│ Python sidecar (FastAPI)   │
        └────────────────┘  127.0.0.1:<random>   │  Job Manager               │
                            + session token      │  Modules: pdf / media / ai │
                                                 │  Index Service             │
                                                 │  Model Manager             │
                                                 └────────────┬───────────────┘
                                                              │
                              SQLite (+ sqlite-vec) · encrypted vault file · model cache
```

## 3. Responsibility split

| Concern | Layer | Why |
|---|---|---|
| Tray, global hotkeys, autostart | Rust | Must work with no window and no Python running |
| Clipboard history capture | Rust | Always-on, low memory; Python is not kept alive for it |
| Color picker, Pin-to-Screen, Live Text overlay | Rust (+ OCR call to sidecar) | Needs native windows/capture APIs |
| File watching, disk scan, duplicate hashing, bulk rename | Rust | Fast, no GIL, low idle cost |
| PDF, OCR, conversion | Python | PyMuPDF and the OCR/Office ecosystem |
| Whisper, upscaler, background removal, RAG, LLM | Python | ML ecosystem |
| Video/image batch processing | Python orchestrating ffmpeg | Job-managed, cancellable |

The Python sidecar is started lazily when a Python-backed feature is first used and stopped after an idle timeout. The Rust shell keeps the always-on features (clipboard, watchers, rules) running without it.

## 4. Local API security

Anything listening on localhost can be called by any website the user visits, so the API is locked down:

1. Bind to `127.0.0.1` only (never `0.0.0.0`).
2. Random free port chosen by Tauri on every launch and passed to the sidecar.
3. Per-session secret token generated by Tauri, passed to the sidecar via environment variable and to the UI via IPC. Every request must send it (`Authorization` header); WebSocket/SSE use a short-lived ticket.
4. Strict `Origin` check and no permissive CORS.
5. File-path inputs are validated against user-approved locations; the API never exposes arbitrary file read/write.
6. The optional Local Exposer can only forward user-chosen ports and must refuse the sidecar's own port.
7. Local-network features (LocalDrop) use a separate listener with pairing/PIN and TLS, never the main API.

Development mode uses a fixed port and `LOCALFLOW_DEV_TOKEN` for convenience; it is disabled in release builds.

## 5. Job Manager

Long-running work (Whisper, upscaling, video compression, OCR of big PDFs, indexing) goes through one job system:

- Jobs run in a process pool (not threads, because of the GIL and so they can be killed on cancel).
- Each job has: id, type, params, state (`queued → running → done | failed | cancelled`), progress, log.
- Progress and state changes are streamed to the UI via SSE/WebSocket.
- Cancellation, retries, and concurrency limits per resource class (CPU, GPU, disk).
- Job records persist in SQLite so history survives restarts.

## 6. Modules

Each feature area is a module with a manifest:

```
modules/<name>/manifest.json   # id, version, routes, required models/binaries, permissions
modules/<name>/...             # code
```

- Modules are imported lazily; unused modules cost nothing.
- Manifests declare which models/binaries they need so the Model Manager can prompt for download.
- Modules declare permissions (filesystem scopes, network, clipboard) which the shell enforces and the UI shows.

## 7. Index Service (RAG + semantic search)

One shared pipeline instead of two:

```
file watcher → extractor (PDF/OCR/text/images) → chunker → embedder → sqlite-vec
                                                                    ▲
                      Local RAG chat ───────────────────────────────┤
                      Semantic file search ─────────────────────────┘
```

- Index scopes are user-chosen folders; nothing is indexed by default.
- Embedding model and chat LLM are managed by the Model Manager (llama.cpp or Ollama runtime).
- `sqlite-vec` (or LanceDB) is used instead of a client/server vector DB so the store is a single local file and requires no extra service. pgvector is intentionally not used (needs a Postgres server).

## 8. Model Manager

- Registry of known models (Whisper sizes, Real-ESRGAN, rembg, embedding model, LLMs) with size, license, and hardware requirements.
- Hardware detection (CPU features, GPU vendor, CUDA/DirectML availability) to suggest suitable models.
- Download with resume and checksum verification; cache in a user-configurable directory; delete from the UI.
- Nothing is downloaded at install time; features that need a model prompt on first use.

## 9. Storage

SQLite database (WAL mode) holds:

| Table group | Contents |
|---|---|
| settings | App and per-module settings |
| rules | Rule Engine definitions |
| clipboard | History (encrypted at rest), pinned items, scratchpad |
| jobs | Job records and logs |
| undo_log | Every file operation with enough data to revert it |
| assets | Quick Asset Library metadata (files stored on disk) |
| vectors | `sqlite-vec` tables for the Index Service |

## 10. Rule Engine and the Undo Log

Rules are `trigger → conditions → actions`:

- Triggers: file created/modified in folder, schedule, hotkey, manual.
- Conditions: extension, name regex, size, age, content type, OCR/text match.
- Actions: move, copy, rename, compress, OCR, convert, notify, run another rule.

Every action that changes the filesystem:

1. Supports dry-run and shows a preview.
2. Moves files to Recycle Bin / a quarantine folder instead of deleting.
3. Appends an entry to `undo_log` (operation, source, destination, timestamp) before it executes.

Downloads Autopilot, Bulk Renamer, System Cleaner, and Dev-Junk Sweeper are presets/clients of this system rather than separate engines.

## 11. Encrypted Vault

- Key derivation: Argon2id from the master password, with per-vault random salt and tuned memory/time cost.
- Encryption: AES-256-GCM (authenticated) with per-file nonces; file names and metadata are inside the encrypted container.
- Mandatory recovery key generated at creation and shown once; without the password and the recovery key, data cannot be recovered.
- Keys exist in memory only while the vault is unlocked and are zeroed on lock/idle timeout.
- The vault must not be the only copy of anything the user cares about until backup/export is available; the UI states this.
- Clipboard capture ignores content copied from unlocked vault views.

## 12. Packaging

- Tauri bundles the Rust shell and UI.
- The Python sidecar is built into a self-contained executable (e.g. PyInstaller) with **only the core modules** (PDF, rules glue, Job Manager).
- Heavy dependencies (ONNX runtimes, Whisper, LLM runtime, upscaler) are optional packs installed through the Model Manager.
- ffmpeg is bundled; LibreOffice is detected and, if missing, the Office → PDF feature explains how to enable it.
- Updates via the Tauri updater; models and optional packs update independently.

## 13. Platform notes

Windows is the primary target. OS-specific code (clipboard formats, screen capture, overlay windows, temp paths, Recycle Bin, Explorer context menu) is isolated behind traits in the Rust layer so macOS/Linux ports only add implementations.

## 14. Open questions

- llama.cpp embedded vs Ollama as the LLM runtime (embedded = fewer moving parts; Ollama = reuse of user's existing models).
- `sqlite-vec` vs LanceDB maturity at the expected index sizes.
- Whether to adopt the LocalSend protocol for LocalDrop or drop the feature.
- Whether the Vault should wrap an existing tool (`age`, VeraCrypt) instead of a custom container.


## 15. Photo editing engine

`backend/localflow/modules/photo/` renders an **edit list**: a list of operations (crop, rotate, adjust, blur, text, ...) applied in order to the photo.

- Geometry is normalized (0..1 of the image at that step) and every pixel length is in pixels of the original image. Each pixel length is multiplied by `scale`, the ratio of the working image to the original, so a small preview and the full-resolution export show the same picture. A test measures the difference between the two.
- The UI sorts edits by stage (geometry, privacy blur, tone, filter, finish, drawing, frame) before sending them, so a tone change never recolors text.
- Previews work on a cached, downscaled copy of the photo; export and batch run as jobs on the full file.
- Text, shapes, logos and blur areas are objects in the edit list. The preview also reports where text and pictures landed (`boxes`), so the editor can draw selection frames exactly on them; the UI hides a text while it is being retyped in place.
- `result_size` is computed without rendering, and a test checks it against real exports for every geometry edit (including Pillow's exact rounding for arbitrary rotation angles).

## 16. PDF editor engine

`backend/localflow/modules/pdf/edit.py` adds content on top of pages: text, images, markup, shapes, notes, links, erase and redact, plus page-level tools (headers and page numbers, crop, resize, insert, split, extraction, forms, properties).

- All coordinates are in the page **as displayed** (points, origin top-left, after the page rotation). The engine converts to PDF space, so everything is correct on rotated pages; tests cover 0, 90, 180 and 270 degrees.
- Erase and redact run first because they delete content; everything else is added afterwards.
- The editor draws every placed item itself (text, shapes, images, notes) as live objects in page points, so selecting, moving, resizing and retyping need no round trip. The saved file is produced by the engine from the same list of edits.

### Text that stays searchable

Many Windows fonts draw several characters with one shared glyph (space and non-breaking space, hyphen and soft hyphen, semicolon and Greek question mark). When such a font is embedded, PDF readers extract the other character, so searching a document for `REF-0006` finds nothing. `pdf/textwrite.py` measures once per font file which characters come back wrong and writes only those with the matching built-in font (Helvetica, Times or Courier), in strict left-to-right order so extraction keeps one line. Page numbers, edits and watermarks all go through it.

## 17. Window and layout

The native window frame is disabled; the shell draws its own title bar (drag region, minimize, maximize, close) and the tool list can be folded away. The two editors fold it automatically so they use the whole window. The end-to-end suite caught the layout bugs this introduced (a collapsed grid column, a zero-height editor) by measuring real element boxes.
